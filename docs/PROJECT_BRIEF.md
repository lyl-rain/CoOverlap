## 1. 项目背景与科学问题

项目名称：CoOverlap: Predictable Chunked VLA Execution on Embedded GPUs，面向嵌入式 GPU 的可预测分块 VLA 执行。

真实 VLM 子块和周期性 Expert 在嵌入式 GPU 上竞争资源。空间分区可能使二者重叠，也可能产生干扰和闲置配额；较大的执行块减少启动开销，却增加 Expert 在合法边界前的等待。项目研究固定模型计算和周期预算下，如何组织 GPU 执行，使完整 VLM 刷新更早就绪，或显著降低周期违约率，同时保持 Expert 时限与完整 VLM 进度。

研究对象是 GPU 执行组织和实时行为，不是动态感知、模型训练、量化、减少计算量、能量最优化或机器人闭环任务成功率。

## 3. 两条候选研究路线

### B1：TPC 级选择性弹性共执行

以真实 VLM 子块和 Expert 的配对 profiling 为依据，只让净收益为正的子块同跑。Expert 的 GPU 工作完成后，在下一个合法子块边界为尚未启动的 VLM 工作归还资源。研究重点是量化并消除小 GPU 上的固定分区损失，同时维持 Expert 时限与 VLM 有界进度。

不能迁移或扩容正在执行的 GEMM。掩码设置、实际生效、边界等待和图启动开销必须计入净收益。动态配额、lockstep、双流和 CUDA Graph 等已有能力不能直接作为本项目的新贡献。

### B2：受时限约束的切分与可预测时分执行

根据真实子块耗时分布选择合法执行图边界，在边界处优先安排 Expert，并跨周期保存 VLM 状态。块越大，启动次数越少但 Expert 可能等待更久；块越小，等待可能缩短但启动、同步和状态维护开销增加。研究重点是以可解释的切分与计划，在固定负载和预算下降低尾部违约，并保留完整刷新进度。

CUDA Graph 本身不是新贡献；需通过消融证明收益来自切分、优先次序和余量计划。

### 路线选择

第一周在目标板上验证真实负载、配额及两档周期预算后，只选择一条路线作为后续主贡献。若在目标工作区间，B1 相对同等优化串行方案获得稳定的净 VLM 进度或刷新时间收益，并满足相同违约要求，可提议 B1；若净重叠被干扰、粗粒度或切换开销抵消，则依据实测阻塞与尾延迟提议 B2。不得只凭单次最好均值或宽松预算点决定。最终路线须经用户确认。用户 2026-10-18 已决定暂不选线、保留 B2 建议；这是用户主动延期，不是遗漏，也不等于已选 B2。2026-10-20 用户随后表示“我准备尝试选用B2”，当前工作方向更新为B2试选；保留其尝试性质，最终定线尚未确认。随后初始GPU短批曾在S0门槛FAIL；此后用户批准诊断、探针及D1，M2 v3已通过有限正确性/版本/回放机制验收。随后clean_serial_v1唯一批已取得有限阶段公平串行基线，仍未取得B2收益；本批额度已执行完并停止；后续用户仅授权M3 B2候选源码/CPU/方案准备，已交付独立协议和唯一短profiling计划，尚无新GPU或机制收益证据。

## 4. 主要指标与公平口径

主实验使用固定周期 `P`，相对 deadline `D`，且 `P = D`。第 `j` 个周期的释放点为固定时钟确定的 `r_j`，不能由前一周期的实际完成时刻重置。

- 周期响应时间：从 `r_j` 到当期全部必做工作完成，包括等待；迟到周期仍计入统计。
- p99、p99.9：周期响应时间分布的尾部分位，不代表形式化最坏情况保证。
- Deadline miss ratio：违约周期数 / 总周期数；同时报告原始计数和最长连续违约。
- `W(D)`：预算 `D` 内按时完成的固定 VLM 工作单元。
- 完整刷新就绪时间：从刷新释放和输入快照固定，到全部 VLM 工作完成且新 KV 发布的真实墙钟时间，包含跨周期等待。
- `k`：一次完整刷新跨越的周期数；`k_min`：在预先规定的违约要求下，实测可行的最小周期数。
- `k_model`：任务书连续可分理论算例中的下界，不是实测 `k_min`。

先比较固定 `k` 下相同工作量的周期表现，再扫描固定预算下的 `W(D)`、`k_min` 和刷新就绪时间。不能把 `k` 减半自动解释为刷新墙钟时间减半，也不能丢弃迟到作业或长期延后 VLM 工作。

历史 NX 的 36+17+3 ms 是复测线索；任务书的连续模型表是注明假设的算例。二者都不是 AGX 数据或性能预测。

## 5. M1 三级验证与公平基线

M1 必须分别给出三层证据，不能以后一级结论替代前一级结论：

1. **GPU 分区确实生效：**核对实际 SM/TPC 配置，使用 SM 分布或执行探针与配额响应，不能只凭 API 成功或带宽变化。若工具不暴露 TPC 映射（本机即如此），记录工具边界；不得把 SM ID 当成 TPC 拓扑。
2. **真实算子能够正确同跑：**以真实 VLM 子块和 Expert 检查数值一致性、GPU 时间线和实际重叠；创建两个 stream 本身不构成证据。
3. **计入全部开销后的完整执行确实改善：**同一固定负载比较端到端周期与刷新结果，将干扰、掩码设置与生效、边界等待、图启动及同步成本计入；只看到局部重叠不构成完整收益。

主要基线为：同等优化的串行执行、普通双 stream、调优后的固定分区、Robion 风格 lockstep 移植、边界 Expert 优先时分，以及最终机制和必要消融。通用优化应对基线对称开放；冷启动与稳态、profiler 诊断与正常性能计时分开。这些是后续/正式评测基线，不在首周全部要求；M1 完成的是有限四模式与隔离配额响应。

任务书规定六张主图：

1. 机会观察：分区损失，或块粒度与边界阻塞。
2. 执行时间线：串行、双 stream、固定分区与最终计划。
3. 固定 `k`：周期延迟分布与违约率。
4. 固定预算：`W(D)`、`k_min` 与完整刷新就绪时间。
5. 机制消融：隔离各设计环节的贡献。
6. 部署稳定性：NX、受控干扰与长运行。

Robion、EagleVLA、libsmctrl、Green Context 官方文档及任务书列出的相关资料是后续必读线索；引用所述结论仍须阅读原论文或官方资料并核对目标版本。本轮未安装/验证 libsmctrl；Green Context 作为同等验收替代，TPC 级控制仍需另批工具验收。
