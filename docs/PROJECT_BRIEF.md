# CoOverlap 项目简报

## 文档定位

本文供各阶段独立对话快速了解项目，不替代项目根目录的 `Student_B_CoOverlap_Revised.docx`。任务书原文是研究要求与边界的最终依据。本文中的“挑战目标”和机制分析均不表示已有实验结果。

## 1. 项目背景与科学问题

项目名称：CoOverlap: Predictable Chunked VLA Execution on Embedded GPUs，面向嵌入式 GPU 的可预测分块 VLA 执行。

真实 VLM 子块和周期性 Expert 在嵌入式 GPU 上竞争资源。空间分区可能使二者重叠，也可能产生干扰和闲置配额；较大的执行块减少启动开销，却增加 Expert 在合法边界前的等待。项目研究固定模型计算和周期预算下，如何组织 GPU 执行，使完整 VLM 刷新更早就绪，或显著降低周期违约率，同时保持 Expert 时限与完整 VLM 进度。

研究对象是 GPU 执行组织和实时行为，不是动态感知、模型训练、量化、减少计算量、能量最优化或机器人闭环任务成功率。

## 2. 平台与固定负载

- 主平台：NVIDIA Jetson AGX Orin 64GB，Codex 已通过授权 SSH 访问。Orin NX 用于粗粒度对照。
- 已验证范围：CUDA设备视图16SM、合法8SM点及短探针；固定Pi0.5 BF16、双视角、49语言token/561Encoder长度、18层、50动作长度、10步Expert的Eager完整/双块路径；固定旧v0/构建v1的顺序恢复；v4两预算各三独立进程及安全干扰。限定Encoder四模式曾数值及Event有限通过，历史Vision并发FAIL保留。候选尚未选为论文主负载。
- 当前交付：v4两预算各三独立进程/24格、安全固定干扰，v7限定Encoder四模式正常12样本/成本，v9四诊断完整Kernel/correlation/实际重叠及B2路径生效均已实测。M1第一周有限测量与产物已交齐，可提交收口审核；v7归还优于固定点但未胜串行，当前双块周期无稳定改善。最终验收/路线待用户确认，M2未启动。历史Vision并发FAIL、v5/v6 Context FAIL及Graph UNKNOWN保留，未穷尽闭源Kernel物理SM集合/全配额优化/长期尾部不是新增首周前置。详见`PROJECT_STATUS.md`和`reports/m1_acceptance/M1_FINAL_REPORT.md`。
- 主实验固定 checkpoint、模型精度、去噪步数、输入形状、视角、token 数、单次 VLM 刷新工作量和每周期 Expert 工作量。
- 每组实验锁定 GPU、CPU、EMC 频率，并记录实际频率、温度、设备模式与软件版本；任何实际硬件配置操作须遵守 `AGENTS.md` 的事先批准规则。
- 完整刷新使用固定输入快照。跨周期保留正确的激活与 KV 状态；Expert 在一次完整去噪期间消费固定版本。新 KV 完全就绪后发布，旧缓冲在所有 GPU 读者完成后才能复用。

## 3. 两条候选研究路线

### B1：TPC 级选择性弹性共执行

以真实 VLM 子块和 Expert 的配对 profiling 为依据，只让净收益为正的子块同跑。Expert 的 GPU 工作完成后，在下一个合法子块边界为尚未启动的 VLM 工作归还资源。研究重点是量化并消除小 GPU 上的固定分区损失，同时维持 Expert 时限与 VLM 有界进度。

不能迁移或扩容正在执行的 GEMM。掩码设置、实际生效、边界等待和图启动开销必须计入净收益。动态配额、lockstep、双流和 CUDA Graph 等已有能力不能直接作为本项目的新贡献。

### B2：受时限约束的切分与可预测时分执行

根据真实子块耗时分布选择合法执行图边界，在边界处优先安排 Expert，并跨周期保存 VLM 状态。块越大，启动次数越少但 Expert 可能等待更久；块越小，等待可能缩短但启动、同步和状态维护开销增加。研究重点是以可解释的切分与计划，在固定负载和预算下降低尾部违约，并保留完整刷新进度。

CUDA Graph 本身不是新贡献；需通过消融证明收益来自切分、优先次序和余量计划。

### 路线选择

第一周在目标板上验证真实负载、配额及两档周期预算后，只选择一条路线作为后续主贡献。若在目标工作区间，B1 相对同等优化串行方案获得稳定的净 VLM 进度或刷新时间收益，并满足相同违约要求，可提议 B1；若净重叠被干扰、粗粒度或切换开销抵消，则依据实测阻塞与尾延迟提议 B2。不得只凭单次最好均值或宽松预算点决定。最终路线须经用户确认。

## 4. 主要指标与公平口径

主实验使用固定周期 `P`，相对 deadline `D`，且 `P = D`。第 `j` 个周期的释放点为固定时钟确定的 `r_j`，不能由前一周期的实际完成时刻重置。

- 周期响应时间：从 `r_j` 到当期全部必做工作完成，包括等待；迟到周期仍计入统计。
- p99、p99.9：周期响应时间分布的尾部分位，不代表形式化最坏情况保证。
- Deadline miss ratio：违约周期数 / 总周期数；同时报告原始计数和最长连续违约。
- `W(D)`：预算 `D` 内按时完成的固定 VLM 工作单元。
- 完整刷新就绪时间：从刷新释放和输入快照固定，到全部 VLM 工作完成且新 KV 发布的真实墙钟时间，包含跨周期等待。
- `k`：一次完整刷新跨越的周期数；`k_min`：在预先规定的违约要求下，实测可行的最小周期数。
- `k_model`：任务书连续可分理论算例中的下界，不是实测 `k_min`。

先比较固定 `k` 下相同工作量的周期表现，再扫描固定预算下的 `W(D)`、`k_min` 和刷新就绪时间。不能把 `k` 减半自动解释为刷新墙钟时间减半，也不能丢弃迟到作业或长期延后 VLM 工作。

历史 NX 的 36+17+3 ms 是复测线索；任务书的连续模型表是注明假设的算例。二者都不是 AGX 数据或性能预测。

|---|---|---|

## 5. M1 三级验证与公平基线

M1 必须分别给出三层证据，不能以后一级结论替代前一级结论：

1. **GPU 分区确实生效：**核对实际 SM/TPC 配置，使用 SM 分布或执行探针与配额响应，不能只凭 API 成功或带宽变化。
2. **真实算子能够正确同跑：**以真实 VLM 子块和 Expert 检查数值一致性、GPU 时间线和实际重叠；创建两个 stream 本身不构成证据。
3. **计入全部开销后的完整执行确实改善：**同一固定负载比较端到端周期与刷新结果，将干扰、掩码设置与生效、边界等待、图启动及同步成本计入；只看到局部重叠不构成完整收益。

主要基线为：同等优化的串行执行、普通双 stream、调优后的固定分区、Robion 风格 lockstep 移植、边界 Expert 优先时分，以及最终机制和必要消融。通用优化应对基线对称开放；冷启动与稳态、profiler 诊断与正常性能计时分开。

任务书规定六张主图：

1. 机会观察：分区损失，或块粒度与边界阻塞。
2. 执行时间线：串行、双 stream、固定分区与最终计划。
3. 固定 `k`：周期延迟分布与违约率。
4. 固定预算：`W(D)`、`k_min` 与完整刷新就绪时间。
5. 机制消融：隔离各设计环节的贡献。
6. 部署稳定性：NX、受控干扰与长运行。

Robion、EagleVLA、libsmctrl、Green Context 官方文档及任务书列出的相关资料是后续必读线索；引用所述结论仍须阅读原论文或官方资料并核对目标版本。

## 6. 阶段计划

| 阶段 | 目标 | 验收产物 |
|---|---|---|
| M1 第一周真实负载验证 | 验收软件、配额、真实算子和数值；测配对干扰、固定分区损失、宽松及紧预算；提出路线建议 | 路线选择报告、机会观察图、完整原始 trace |
| M2 最小执行器与正确性 | 建立固定输入回放、版本 KV、合法子块执行、统计和公平串行基线 | 数值及版本检查、可复现周期回放 |
| M3 选定路线的核心机制 | 实现经用户确认的 B1 选择性与归还，或 B2 切分与时分计划 | 净收益与开销分解、关键消融 |
| M4 大收益指标验证 | 固定 `k` 和固定预算的完整曲线及独立长回放 | 完整刷新或违约率主张的实测证据 |
| M5 稳健性与论文 | NX 对照、受控干扰、热稳定运行及论文写作 | 六张主图、复现实验材料、论文初稿 |

B1 的“`k_min` 约减半、刷新就绪时间约缩短 50%”及 B2 的“违约率约降低 10 倍”是挑战目标。尚无本项目实验结果支持这些数值。

## 7. 最小工程模块

`replay_driver` 负责固定轨迹释放；`pair_profiler` 负责真实配对测量；`versioned_kv` 负责双版本发布与安全复用；`block_runner` 负责合法子块/子图运行；`execution_plan` 负责边界、资源和次序选择；`deadline_stats` 负责周期与完整刷新统计。两条路线共用正确性、回放、日志和统计基础。
